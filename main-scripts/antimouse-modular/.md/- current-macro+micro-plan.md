**User Feedback Summary:**

2.  **Subgrid Activation:** The subgrid should activate automatically whenever the cursor enters *any* main grid cell (like the highlight), not just on initial activation or after a two-key selection.

**Analysis of Current Logic & Issues:**

1.  **Post-Spacebar Issue:**
    *   **Current Logic:** `Space::` hotkey (`hotkeys.ahk`) stops tracking, sets state to `IDLE`, hides GUIs, performs `Click`, then calls `Cleanup()`. `Cleanup()` (`activation.ahk`) stops tracking again, transitions to `IDLE` (hiding GUIs), resets flags and state variables, *destroys* GUI objects (`highlight.Destroy()`, `subGrid.Destroy()`, `overlay.Destroy()`), clears the global variables holding these objects (`highlight := ""`, etc.), and calls `ForceCloseAllGuis()`. Subsequent activation via `CapsLock_Q()` *recreates* all these GUI objects.
    *   **Problem:** The failure suggests that either the `Cleanup` process isn't fully completing (leaving orphaned windows/handles despite `Destroy` and `ForceCloseAllGuis`), or the *re-creation* process in `CapsLock_Q` is failing silently (perhaps due to lingering state or an error during GUI creation/showing). The tooltip appearing indicates `CapsLock_Q` starts, but visual elements fail later.

2.  **Subgrid Activation Issue:**
    *   **Current Logic:** Subgrid activation (`TransitionToState(State_SUBGRID_STANDARD)`) occurs only in two places:
        *   `CapsLock_Q()`: If the cursor is *already* inside a cell when the grid is first activated.
        *   `HandleSecondKey()`: After a valid two-key (Col+Row or Row+Col) sequence is entered.
    *   **Hover Activation Logic:** The code for activating the subgrid when the cursor *hovers* into a cell (`TrackCursor()` in `tracking.ahk`) is explicitly **commented out** (`--- REMOVED HOVER ACTIVATION ---`). This was likely done previously to fix race conditions (Task 5.10) where hovering and pressing keys simultaneously caused issues.
    *   **Problem:** The user *wants* the hover activation behavior back, but it needs to be implemented robustly to avoid the previous conflicts.

**Needed Areas of Work:**

1.  **Cleanup & Activation Robustness:** Ensure the cleanup process is bulletproof and that subsequent activations reliably recreate and display the necessary GUI elements.
2.  **Hover-Based Subgrid Activation:** Re-implement the logic for the subgrid to appear automatically upon hovering over a main grid cell, while preventing conflicts with key presses.

**Suggested Robust Approach & User Experience:**

1.  **Cleanup/Activation:**
    *   **Refined Cleanup:** Instead of relying heavily on `ForceCloseAllGuis`, focus on *explicit and ordered* destruction within `Cleanup()` and `DeactivateGrid()`.
        1.  Stop Timers (`TrackCursor`).
        2.  Transition State (`TransitionToState(State_IDLE)`) - This should handle initial hiding.
        3.  Reset flags (`inHoldMode`, `gridActivationInProgress`).
        4.  Reset `StateMap` data (keys, indices, ultra-fast state).
        5.  **Crucially:** Iterate through `StateMap['overlays']`, `highlight`, `subGrid`. Check `IsObject()` *before* calling `.Destroy()` on each. Wrap destruction in `try/catch`.
        6.  **Crucially:** *After* destroying, explicitly set the global variables to empty strings (`highlight := ""`, `subGrid := ""`, `StateMap['overlays'] := []`, `StateMap['currentOverlay'] := ""`). This breaks the references cleanly.
    *   **Activation Verification:** In `CapsLock_Q`, after creating GUI objects (`highlight`, `subGrid`, `overlays`), add checks (`if (!IsObject(highlight))` etc.) and log/notify if creation failed *before* attempting to show or transition state.

2.  **Hover Activation:**
    *   **Re-enable Logic:** Uncomment the hover activation block in `TrackCursor()`.
    *   **Prevent Race Conditions:**
        *   **Keypress Debounce:** Introduce a state variable like `StateMap['lastKeypressTime']`. In `ProcessKeyPress` (or more specifically, when `HandleKey` is called for a *grid* key), set `StateMap['lastKeypressTime'] := A_TickCount`. In `TrackCursor`, before triggering the hover activation (`TransitionToState(State_SUBGRID_STANDARD)`), add a check: `if (A_TickCount - StateMap.Get('lastKeypressTime', 0) < 150) { highlight.Update(...); return; /* Don't transition yet */ }`. This ensures that if a grid key was pressed very recently, hover activation waits, letting the keypress logic take precedence.
        *   **First Key Check:** Retain the existing check `if (StateMap['firstKey'] == "")` within the hover logic. This correctly prevents hover activation if the user has already started a two-key selection sequence.
    *   **UX:** This provides the desired immediate feedback – the subgrid appears as soon as the user hovers over a cell (unless they *just* pressed a key), making navigation feel more fluid and intuitive, matching the highlight's behavior. The debounce prevents accidental activation during typing.
